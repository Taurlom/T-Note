# Changelog — T-Note

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
проект придерживается [семантического версионирования](https://semver.org/lang/ru/):

- **MAJOR** — несовместимые изменения концепции приложения;
- **MINOR** — новые пользовательские возможности;
- **PATCH** — исправления и мелкие доработки.

`versionCode` в `app/build.gradle.kts` вычисляется из `versionName`:
MAJOR·10000 + MINOR·100 + PATCH (например, 1.6.0 → 10600).
До 1.14.0 включительно действовала формула MAJOR·100 + MINOR·10 + PATCH
(1.14.0 = 240), поэтому минимально допустимый `versionCode` для новых
сборок — 241. Релиз помечается аннотированным тегом `vX.Y.Z`;
push тега запускает GitHub Actions, который собирает подписанный APK
и прикреплёт его к GitHub Release.

Все выпуски до 1.6.0 восстановлены по истории git и носят обзорный характер:
до внедрения релиз-процесса изменения фиксировались только в сообщениях коммитов.

## [1.15.0] — 2026-10-05

### Добавлено
- Ссылки `mailto:` и `tel:` в заметках: адрес почты открывается почтовым
  приложением, телефон — звонилкой.
- Predictive back (Android 14+): возврат «домой» системным жестом «назад»
  показывает анимированную превью приложения вместо мгновенного
  исчезновения.

### Изменено
- Восстановление из резервной копии устойчиво к сбоям и опасным архивам:
  версия схемы БД читается из SQLite-заголовка копии до подмены живых
  данных — копия из более новой версии приложения отклоняется, не тронув
  текущие данные; сама подмена транзакционна (атомарные переименования
  с откатом при ошибке на полпути); недописанный при сбое файл экспорта
  удаляется. База читается стримингом, а не целиком в память;
  архивы-«бомбы» и слишком большие копии отклоняются лимитами.
  Сообщения об ошибках восстановления стали точнее: «копия из более
  новой версии приложения», «копия не читается», «копия слишком большая».
- Ссылки в заметках открываются только по безопасным схемам
  (http/https/mailto/tel); прочие протоколы (например, `javascript:`)
  рендерятся исходным синтаксисом как обычный текст.

### Исправлено
- Системный жест «назад» в редакторе заметки больше не закрывает экран,
  молча теряя набранный черновик: он идёт по маршруту стрелки тулбара —
  сначала выход из редактора в просмотр, повторный «назад» закрывает экран.

## [1.14.0] — 2026-09-29

### Изменено
- Поворот фото в галерее — правкой EXIF-тега Orientation, а не пережатием
  пикселей: файл не декодируется целиком (раньше весь bitmap ложился в
  память телефона), качество не деградирует, операция занимает миллисекунды.
  Зеркальные варианты тега по-прежнему поворачиваются пикселями.
- Окно кропа показывает фото прямым с учётом EXIF, а region-декодер
  пересчитывает рамку в «сырые» пиксели с поправкой на ориентацию —
  кроп повёрнутого фото теперь режет ровно то, что видно.

### Исправлено
- Все файловые операции с фото документов и заметок исполняются на IO-потоке:
  копирование выбранных снимков, удаление файлов, поворот и сохранение
  кропа больше не блокируют UI (подтормаживания и риск ANR при работе с
  тяжёлыми фото). Кнопки поворота/кропа блокируются на время операции.
- Кроп фото больше не режет уменьшенную копию: выбранная область
  декодируется из оригинала в полном разрешении (BitmapRegionDecoder,
  пересчёт рамки в пиксели источника, потолок 4096 px против OOM).
  Раньше фото 4000×3000 после кропа физически не могло быть больше
  2048 px; теперь кроп сохраняет разрешение исходника. Оригиналы,
  как договорились, не хранятся — кроп по-прежнему заменяет файл.

  Применятся сразу, бар перестраивается под диалогом; последний видимый
  раздел скрыть нельзя; выбор хранится в DataStore, при повреждённом
  списке — порядок по умолчанию.

## [1.11.2] — 2026-09-25

Переходный релиз для миграции со старых legacy-сборок
(`com.example.timemanager`): ставится поверх 1.10.x/1.11.x с сохранением
данных (подпись совпадает), делает диагностирующую резервную копию —
далее данные переносятся в `ru.taurlom.tnote` восстановлением, старое
приложение удаляется.

### Исправлено
- Конвертация «День рождения → Обычное» больше не затирает год рождения
  датой просматриваемого вхождения и не роняет ежегодный повтор: при
  редактировании дата строки всегда сохраняется (кроме «Выходного»,
  который намеренно помечает открытый день).
- Кроп фото документа: путь заменяется перечитыванием документа из базы,
  устаревший снапшот UI больше не затирает соседние правки и не оставляет
  файлы сиротами.
- Редактирование документа: файлы фото удаляются только после коммита базы,
  список фото мержится со свежим снапшотом (гонка с кропом закрыта).
- Сохранение фото: если источник не открылся (URI истёк после камеры),
  путь не записывается в документ — больше нет ссылок на несуществующие файлы.
- Заметки календаря: одна заметка на день (eventDate — первичный ключ,
  миграция 13→14 оставляет последнее сохранение и убирает накопленные дубли).
- Миграция 5→6: переставлена так, чтобы не терять document_photos каскадом
  (Room выполняет миграции в транзакции, где PRAGMA foreign_keys — no-op).

### Добавлено
- Самодиагностика резервных копий: экспорт считает осиротевшие фото, пишет
  время записи каждого файла и метаданные в манифест — видно, что именно
  уже потеряно, до того как переносить данные в новый пакет.

### Добавлено

  (`values-en`, `values-es`, 127 строк каждый). Приложение следует языку

- Палитра цветов категории — общий компонент `AppColorPicker` с переносом

  ресурсы и переводится: названия тем (Dark / Oscura…), названия месяцев и

  (назад, редактировать, удалить, повернуть, обрезать, стрелки месяцев).
- Названия месяцев и дат форматируются по языку конфигурации контекста,
  а не по жёстко заданному русскому.
- `MainActivity` — на `AppCompatActivity` (нужно для per-app языков на
  Android < 13); темы окна переведены на AppCompat-наследие.

## [1.10.0] — 2026-09-24

### Добавлено
- Пересылка списков файлом `.tnote`: в диалоге «Поделиться списком» второй
  вариант — файл для T-Note (JSON с версией формата `tnoteList: 1`, порядком

  лимиты длины и количества пунктов, размер до чтения. 7 юнит-тестов codec.

### Изменено
- Кнопка «Следующий» при добавлении задачи доступна с первого пункта
  (раньше появлялась только в непустом списке).
- Иконка типа события «День рождения»: подарок заменён на залитый торт
  (Material Symbols cake, fill) — в списке типов, строках событий и
  маркере календаря.

## [1.9.0] — 2026-09-24

### Добавлено
- «Поделиться списком»: кнопка в шапке экрана задач отправляет список текстом
  (название + пункты с отметками выполнения и описаниями) в любой мессенджер,

  темах; панель плавно меняет цвет, когда контент прокручен под неё.

  для сверки с релизами.

## [1.8.0] — 2026-09-23

### Добавлено
- Резервные копии в настройках: экспорт всех данных одним zip-файлом
  (база Room, фотографии документов, выбранные тема и шрифт) и восстановление
  из него. Работает офлайн, без сетевых разрешений — файл выбирается через
  системный диалог (SAF). Перед экспортом WAL-журнал базы сливается в файл,
  архив проверяется по манифесту (в т.ч. от zip slip), восстановление требует
  подтверждения и перезапуска приложения.
- Раздел «Резервные копии» в возможностях README.

### Изменено
- Отладочные сборки подписываются релизным ключом: debug- и release-сборки
  для Android теперь «одно приложение» и обновляют друг друга без
  переустановки и потери данных. Флаг `-PkeepDebugSigning` оставляет
  обычный отладочный ключ — он нужен был для переходного билда с экспортом,
  который ставился поверх приложений, подписанных старым debug-ключом.

## [1.7.0] — 2026-09-23

### Добавлено
- Цветовая тема «Осень» (тёплая кофейно-рыжая): пятая в селекторе настроек.
- Единый компонент выпадающего списка `AppDropdown` (поле + меню ширины поля,

- Галерея фотографий на экране документа: вместо горизонтальной ленты мелких

- Чекбокс «Удалять прошедшие» выровнен по левому краю полей: material3 1.3.x
  больше не читает устаревший `LocalMinimumInteractiveComponentEnforcement`,
  отключение 48-dp зоны касания переведено на `LocalMinimumInteractiveComponentSize`.
- `AppTextField` принял параметр `onDarkBackground` — настройки больше не рисуют
  `OutlinedTextField` напрямую.

  и публикует GitHub Release с APK и выдержкой из этого changelog (`.github/workflows/release.yml`).
- CI-проверка каждого пуша и PR: компиляция + юнит-тесты (`.github/workflows/ci.yml`).
- Подпись релизов отдельным ключом (keystore + секреты репозитория),
  настройка через `keystore.properties` (вне репозитория).
- Версионирование синхронизировано: `versionName`/`versionCode` теперь
  соответствуют тегу и этому changelog (раньше в Gradle числилась 1.0).

- Структура репозитория: из git исключены артефакты сборки (`app/build/generated`),

- Обновлены README и документация проекта.

## [1.5.0] — 2026-09-22

- Поле «Повторять» (раз в день/неделю/месяц) у событий календаря: остался
  только интервал «раз в сколько дней». Миграция БД (v13) пересчитывает
  ранее заданные периоды в дни (день=1, неделя=7, месяц=30) без потери частоты.
