# T-Note

Персональный планировщик для Android: списки задач, заметки с форматированием,
календарь событий и база документов с фотографиями — полностью офлайн,
без аккаунтов и сети.

## Возможности

**Списки** — категории с цветами; задачи с описанием, отметкой выполнения,
перетаскиванием и копированием в другой список (отметка и завершение
перетаскивания — с короткой вибрацией); отправка списка текстом
в любой мессенджер или файлом `.tnote` — другой пользователь T-Note
импортирует его одним касанием.

**Заметки** — длинный текст с markdown-форматированием: заголовки,
**жирный**, списки, ссылки. К заметке крепятся фотографии (до 10) — сетка
в просмотре и полноэкранная галерея; поворот без потери качества, кадрирование
в родном разрешении. Порядок списка настраивается перетаскиванием,
в превью метки не показываются. Текст из любого приложения отправляется
в T-Note системным «Поделиться» — после подтверждения он становится
заметкой.

**Календарь** — заметки на день; события четырёх типов: обычные
(иконка + цвет), дни рождения (повторяются ежегодно), повторяющиеся
(интервал «раз в N дней», длительность, скрытие прошедших) и «Выходной»
(подсветка дня как Сб/Вс, видна и в соседних месяцах). Навигация:
свайп влево/вправо между разделами, свайп вверх/вниз по календарю —
между месяцами.

**Документы** — карточки с описанием и фотографиями (до 4): галерея
с зумом, поворотом, кадрированием и отправкой фото в мессенджер; съёмка
камерой; порядок списка настраивается перетаскиванием.

**Настройки** — язык интерфейса (Русский, English, Español — по языку
системы или вручную), 5 цветовых тем (Тёмная, Светлая, Океан, Лес, Осень)
и 10 шрифтов, применяются мгновенно. Разделы приложения можно показывать
или скрывать и расставлять в любом порядке («Настройка разделов») —
нижняя панель и стартовый экран подстраиваются.

**Резервные копии** — экспорт всех данных (списки, заметки с фотографиями,
календарь, документы с фотографиями, настройки — тема, шрифт, видимые
разделы) в один zip-файл и восстановление из него. Полностью офлайн:
файл выбирается через системный диалог Android. При создании копия сама
проверяет целостность ссылок на фотографии и сообщает, если что-то из них
отсутствует. Восстановление безопасно: версия схемы и читаемость копии
проверяются до подмены — при любой ошибке данные на устройстве остаются
прежними.

## Технологии

| | |
|---|---|
| Язык | Kotlin 2.4 |
| UI | Jetpack Compose, Material 3 (BOM 2025.02) |
| Архитектура | MVVM + Clean Architecture (domain / data / presentation) |
| Хранилище | Room (миграции), DataStore Preferences |
| DI | Hilt (компилятор на KSP) |
| Навигация | Navigation Compose + HorizontalPager для разделов |
| Изображения | Coil |
| Мин. Android | 24 (target 36) |

## Структура

```
app/src/main/java/com/example/timemanager/
├── data/            # Room (БД, DAO, entity), мапперы, реализация репозиториев
├── di/              # модули Hilt
├── domain/          # модели, интерфейсы репозиториев, use-case
└── presentation/
    ├── components/  # дизайн-система: кнопки, поля, диалоги, карточки
    ├── navigation/  # NavHost + экран разделов (HorizontalPager)
    ├── screens/     # calendar / categories / tasks / documents / notes / settings
    ├── splash/      # заставка
    └── theme/       # цвета-роли, темы, типографика
```

## Сборка

```bash
./gradlew :app:assembleDebug      # отладочный APK
./gradlew :app:testDebugUnitTest  # юнит-тесты
./gradlew :app:assembleRelease    # релизный APK
```

Если `keystore.properties` на месте, debug-сборки подписываются релизным
ключом — debug и release обновляют друг друга без переустановки.
Флаг `-PkeepDebugSigning` возвращает обычный отладочный ключ.

Для подписанного релизного APK нужны файлы вне репозитория
(уже в `.gitignore`): `keystore.properties` в корне и сам keystore.
Формат `keystore.properties`:

```properties
storeFile=signing/timemanager-release.jks
storePassword=...
keyAlias=...
keyPassword=...
```

Без них `assembleRelease` собирает неподписанный APK.

## Каналы установки: два пакета

Начиная с 1.11.1 каждый релиз на GitHub содержит **два APK** — один код и одна
версия, но разные имена пакетов:

| Файл | Пакет | Кому |
|---|---|---|
| `TNote-X.Y.Z-legacy.apk` | `com.example.timemanager` | тем, у кого T-Note установлен с давних пор: обновляется поверх, данные на месте |
| `TNote-X.Y.Z-store.apk` | `ru.taurlom.tnote` | новым установкам; идентичен сборкам в магазинах (RuStore, далее Google Play) |

Зачем два: имя пакета — это идентичность приложения на устройстве и в магазине.
Префикс `com.example` зарезервирован Google Play, поэтому магазинная версия
публикуется как `ru.taurlom.tnote`; старый пакет сохранён отдельным каналом,
чтобы не принуждать существующих пользователей к миграции.

Переезд между пакетами — добровольный и одноразовый: в старом приложении
«Настройки → Сохранить копию», установить store-версию (или версию из
магазина), «Настройки → Восстановить из копии». Дальше обновления прилетают
из магазина автоматически.

Локально: `./gradlew :app:assembleRelease` собирает store-пакет,
с `-PlegacyPackage` — старый.

## Релизы

Каждый релиз — аннотированный тег `vX.Y.Z`. Проверка локально:

1. обновить `versionName` (`appVersionName`) в `app/build.gradle.kts` —
   `versionCode` вычисляется из неё автоматически: MAJOR·10000 + MINOR·100 + PATCH
   (например, 1.16.0 → 11600). Сторы требуют, чтобы код каждой загрузки был
   больше предыдущего: исторический минимум — 241, т.к. версии до 1.14.0
   включительно считались по формуле MAJOR·100 + MINOR·10 + PATCH
   (1.14.0 = 240, опубликована в RuStore);
2. добавить секцию в [CHANGELOG.md](CHANGELOG.md);
3. закоммитить и смержить в `main`.

Дальше:

```bash
git tag -a vX.Y.Z -m "T-Note vX.Y.Z"
git push origin main vX.Y.Z
```

Push тега запускает GitHub Actions ([.github/workflows/release.yml](.github/workflows/release.yml)):
CI прогоняет юнит-тесты, собирает подписанный APK (ключ и пароли — из secrets репозитория)
и публикует GitHub Release с файлом и описанием из changelog.

Каждый push в `main` и PR прогоняет компиляцию и тесты
([.github/workflows/ci.yml](.github/workflows/ci.yml)).

Готовые сборки: [releases](../../releases).
